Try it

Type something you would not want on screen.

The same rules the tool applies to each line it reads from your video, running in this page. Nothing you type leaves your browser.

In a real recording the text comes from OCR on each changed frame. This box skips that step, so it is a preview of the rules and not of the whole tool.

What it finds

Ten kinds of text, each checked before it is hidden.

Card numbers must pass the Luhn check. CPF and CNPJ must have valid check digits. Phone numbers are validated per country. Fewer blurred version numbers, fewer misses.

How it works

It reads the screen only when the screen changes.

OCR is the slow part, so most of the design is about running it as little as possible without letting a frame through.

  1. CompareEach frame is compared with the last one that was read. A still screen costs nothing.
  2. ReadWhen the picture changes, the frame goes through OCR on your CPU. Typing only re-reads the strip that changed.
  3. CheckEvery line of text runs through the detectors.
  4. HoldFrames between two reads are held back and covered with the areas from both, so text is hidden from the first frame where it shows up.
  5. FollowWhile the page scrolls, hidden areas follow their pixels instead of waiting for the next read.
  6. DestroyEach area is shrunk to a few pixels and enlarged again. The detail is thrown away, not smeared.

Ask your agent to do it.

Copy the skill from the repository and say what you want. The agent starts the local command and reads its JSON. Your screen is never sent to a model.

you: unleak the recording on my desktop
agent: 14 items hidden: 4 keys, 3 e-mails, 2 phones…

Limits

It lowers the risk. It does not remove it.

  • OCR can miss text that is tiny, stylised or cut off at the edge.
  • A secret typed character by character shows its first characters until the pattern is complete. Paste it instead.
  • Names and addresses are only hidden if you list them with --also.
  • Spoken words in the audio are left alone.
